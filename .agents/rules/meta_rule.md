# 审查与反思元规则 (Meta-Rule)

## 定期排查历史操作记录
- **每次复杂执行（开发、重构、Bug 修复）后**，不要急于汇报工作，必须强制执行一步**「反思流程」**。
- **审视操作历史**：回顾刚才在终端中跑过哪些失败的命令、哪些查询曾抛出异常、哪些配置由于多环境问题导致了歧义和踩坑。
- **记录新课**：检查当前的修复和经验是否已被记录。如果是一个通用的开发避坑点、一个关键的 API 使用限制，或者容易犯错的设计模式，必须提炼并主动总结，**将所有经验统一补充追加到 `.agents/rules/troubleshooting-lessons.md` 文件中**。集中管理踩坑记录，防止在将来的任务中因遗忘上下文而重蹈覆辙。
